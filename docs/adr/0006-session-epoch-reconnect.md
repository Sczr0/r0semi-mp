# ADR-0006：会话纪元——重连编排输入侧闭环

- 日期：2026-08
- 状态：已接受
- 相关章节：ARCHITECTURE.md §4.9-3、§6.5-19/20/21/23

## 背景

重连通知的入队序 ≠ 墙钟序：9.999s 的重连可能排在 10.000s 的定时器之后，盲发 `UserDangleExpired` 会踢掉刚重连的用户。同时，同 id 双活连接（旧 TCP 未关 + 新连接已建）会让两路命令混进同一房间 channel，顺序语义被未定义交织。

## 决策

生命周期事实的单位是 `(user_id, epoch)`：
- `SessionRegistry.register` 每次 +1 并替换（同 id 重连 = 新纪元）；替换时关闭旧 TCP、取消旧会话任务（其死亡事实随之消失）
- 事实携带 epoch，`is_current` 校验——旧会话的死亡事实（`Disconnected`）与过期定时器一律忽略
- `UserDangleExpired` 派发前**先查权威会话状态**（该 user_id 当前是否有活会话）——重连在窗口内则跳过驱逐
- 旧 TCP 到达的命令以 epoch 校验拒绝（防止双活交织）
- 所有 per-user 系统命令（含 `GetClientState`）并入生命周期任务**单一生产者**——顺序问题从源头消除

## 后果

- 正面：输入侧竞态闭环（窗口边界 + 会话纪元 + 旧连接失效 + 单一生产者）；重连编排可测试（epoch 序列有专项测试）。
- 负面：epoch 校验是 core 行为，契约测试（直驱 actor）测不到——需 phira-core 集成测试 + 脚本化假 actor；"表 miss 挂起重放"（幽灵座位第四竞态兜底）**文档承诺但未实现**（ISSUE-0001）。

## 替代方案

- 盲发定时器（到期直接驱逐）——被拒：踢掉刚重连的用户（9.999s 重连排 10.000s 定时器后）。
- 依赖墙钟排序重连通知——被拒：入队序 ≠ 墙钟序是必然，不是偶然。
