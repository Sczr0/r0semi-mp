# ADR-0010：安全锁 A/B——全局在途字节记账 + 已鉴权连接上限

- 日期：2026-08
- 状态：已接受
- 相关章节：ARCHITECTURE.md §10.4（内存 DoS）、§11（连接准入）

## 背景

极端压力目标（CDN/防火墙全炸、持续灌流）下逐项审计发现两个内存洞：
- **洞 1**：§10.4 承诺"每连接解码缓冲记账 + 全局在途字节上限（如 64MiB）"**未实现**——攻击者用真实 token 建立海量已鉴权连接 × 2MiB 大帧（Touches/Judges），每连接 send 队列 1024 × 2MiB = 2GB
- **洞 2**：§11 承诺"总连接数上限"只实现了未鉴权侧（100）；鉴权后连接数**无上限**

## 决策

**安全锁 A（内存硬上限）**：
- 全局 `IN_FLIGHT_BYTES`（进程单例，AtomicUsize）+ 上限 64MiB
- 每连接 `queue_bytes`（AtomicUsize，SendSlot 与写任务共享）
- 投递 Encoded（热路径大帧）时记账：每连接超 8MiB → `force_close`；全局超 64MiB → **丢新 + 断最重连接**（遍历找 queue_bytes 最大）
- 写任务消费实时释放（`fetch_sub` + 全局减）；**写任务任何结束路径**（自然/abort/panic）经 `MemoryReleaser`（Drop guard）释放剩余——**账目必然平衡，无泄漏**

**安全锁 B（连接上限）**：已鉴权连接总数上限 1000（`AUTHED_CONNECTIONS`），超限拒绝鉴权（`server full` + 断开）；收尾释放。

**辅助**：`Stream` 发送类型固定为 `Outbound`（服务端唯一用途；客户端模式测试包一层 `Outbound::Command`）；`Outbound` 实现 `BinaryData`（Encoded 直写缓存字节）。

## 后果

- 正面：内存**硬上限**（全局 64MiB + 每连接 8MiB + 连接数 1000）——攻击下不膨胀、超限即断最重连接、停止灌流即恢复（Drop guard 保证记账平衡）；账目可观测（`in_flight_bytes()`）。
- 负面：记账只针对 Encoded（热路径大帧）——Command 小帧（响应/领域事件 ≤KB 级）不计（1024 × 200B ≈ 200KB/连接，可忽略）；上限是常量（可参数化）；全局 static 是进程单例（多实例各自独立，符合部署模型）。

## 替代方案

- 每连接帧上限收紧（2MiB → 1MiB）——被拒：治标（减半而非封顶）；帧上限是协议语义，收紧可能拒绝合法大包。
- 仅靠队列 DropIfFull（0004）——被拒：防"无限"不防"峰值"（1024 × 2MiB 仍 2GB/连接）。
- 记账用每连接独立计数不设全局——被拒：单连接可防，海量连接总量不可防。
