# ADR-0005：队列压力——按消息类分级

- 日期：2026-08
- 状态：已接受
- 相关章节：ARCHITECTURE.md §4.9-9、§10.4

## 背景

每房间 channel 有界（1024），满时不能一刀切：热路径丢帧自愈（触摸流每帧独立、下一帧自愈），生命周期事实不可丢（丢了 = 幽灵座位/掉线不驱逐），其它客户端命令满则拒（滥用防护）。

## 决策

队列满时按消息类分级处理（`queue_policy`）：
- **DropIfFull（丢新）**：`Touches`/`Judges`/`Tick`——`try_send` 满则拒新包（队内顺序不变，与"同通道保序"相容）
- **Wait（等待）**：`UserDisconnected`/`UserReconnected`/`UserDangleExpired`/`GetClientState`——不可丢，bus 等待入队
- **Reject（拒绝）**：其它客户端命令——`try_send` 失败 → 断连（滥用防护；`§5.6` 新增命令默认归此类）

`RoomClosed` 排空：core 见 RoomClosed 即停路由，新命令回 room-closed 错误；排空期间到达的命令一律 `Failure(Business)`——禁止"加入成功然后房间被拆"。

## 后果

- 正面：热路径永不阻塞、永不因队列问题报错；生命周期事实必达；滥用者被 Reject 断连。
- 负面：丢新 = 丢的是"最新的帧"（文档 §10.4 曾表述"丢旧保新"，mpsc 无法生产者侧驱逐队首——**实际语义是丢新**，ISSUE-0004 修复时确认并记录）；滥用控制**优先**用每连接限速（§4.9-9）——但限速本身未实现（ISSUE-0006），当前靠 Reject 断连兜底。

## 替代方案

- 无限队列——被拒：内存 DoS。
- mpsc 生产者侧驱逐队首（丢旧）——被拒：mpsc 不支持；丢新与保序相容（队内顺序不变）。
