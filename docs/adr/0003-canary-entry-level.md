# ADR-0003：灰度降级——入口粒度，非需求

- 日期：2026-08
- 状态：已接受
- 相关章节：ARCHITECTURE.md §3.2、§1.2

## 背景

协议命令（LeaveRoom/Ready/Played…）不携带 room_id，房间隐含在会话中；L4 LB 在 connect 时刻只有四元组，room_id 首次出现在 CreateRoom/JoinRoom 帧内（协议交换之后）。进程内 A/B 需要 user→impl 影子映射（中间件持有业务状态，必然漂移）；百分比级分流无廉价实现。

## 决策

灰度**降级为非需求**（单人单实例下安全网 = 契约测试 + Oracle + 秒级重启）。未来多实例运营 = **入口粒度**：v2 = 新增服务器入口（独立地址）；灰度 = 引导新房主在 v2 入口建房；回滚 = 下架入口。保留 `Metrics`（原子计数器，错误率只统计 `RoomError::Internal`——业务拒绝是预期行为，混入会扭曲对比）。

## 后果

- 正面：项目内零灰度代码；"同房间同进程"自动成立，零额外机器；错误率对比 = 两个入口各自的 Metrics。
- 负面：百分比级机械分流在该协议下**不可实现**（上限 = 入口级）；若未来真需要，前提是协议加 redirect 命令（记入未来项，不在本项目）。

## 替代方案

- LB 一致性哈希——被拒：L4 LB 看不见哈希键（room_id 在协议载荷里）；按连接分流违反"同房间同进程"；跨进程房间转发需要 redirect/迁移机制（协议没有）——那是伪装成 LB 的第三个服务器。
- 进程内 A/B（Interceptor 中间件）——被拒：影子状态漂移 + 系统命令双写 + 回源翻倍（官方 API 限流），收益不抵复杂度；符合原则 5（v1 没有第二实现）。
