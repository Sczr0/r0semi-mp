# ADR-0007：路由表 miss 挂起重放（幽灵座位兜底兑现）

- 日期：2026-08
- 状态：已接受
- 相关章节：ARCHITECTURE.md §4.9-3（第四竞态·幽灵座位）、§4.9-4（路由规则）

## 背景

§4.9-3 承诺"表 miss 时挂起重放"，但 ISSUE-0001 发现实现是"直接忽略"（lifecycle `dispatch` 表 miss → debug + return）。竞态路径：客户端入房（actor 返回 UserJoined → bus 应用路由增量 → 发响应）后立即断线（RST 即时可见），生命周期任务查表路由 `UserDisconnected` 可能撞上"增量未应用"窗口（bus 忙时拉大）——表 miss → 事实被丢 → 无 dangle 窗口 → 幽灵座位（占坑、无人驱逐）。

## 决策

生命周期任务查路由表 miss 时**挂起重放**：短暂延迟后重查，仍 miss 才放弃。参数：
- `ROUTE_REPLAY_ATTEMPTS = 3`（1 次立即 + 2 次重查）
- `ROUTE_REPLAY_DELAY = 20ms`

覆盖范围论证：真实窗口 = 命令入队 → `process_events` 应用增量之间的 await 点（route 读锁 + actor.handle + 解析读锁），微秒到毫秒级；20ms 重放间隔远大于窗口。ISSUE-0004 修复（deliver 改 `try_send`）已消除投递环节的长时间 await，窗口进一步收窄。

## 后果

- 正面：幽灵座位竞态闭环；正常路径（用户确实不在房间）代价 = 最多 2×20ms 一次性延迟（生命周期是后台任务，可接受）；只影响 miss 路径，命中路径零开销。
- 负面：重放是"时间兜底"而非"精确等待"——极端超大窗口（>60ms）仍可能丢事实；参数是常量（可调），不引入契约变更（core 内部行为）。

## 替代方案

- 精确同步（bus 应用增量后通知 lifecycle）——被拒：跨任务耦合，违背"表写仅经 bus 分发步骤、生命周期只读"的分工（§4.9-3）。
- 表 miss 立即放弃（修复前状态）——被拒：ISSUE-0001，幽灵座位。
- 无限重放直到命中——被拒：用户确实不在房间的常态路径被无限拖住。
